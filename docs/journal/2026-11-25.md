## 03:36 - Handshake drop root cause

- Root cause of "connection open" then "connection closed" in the same second: `colab_mcp.session.ColabProxyClient.await_proxy_connection` does `asyncio.wait_for(gather(connection_live.wait(), self._start_task))`. When that wait times out, or the client cancels the tool call, the gather is cancelled and `_start_task` with it. `_start_task` is the task that builds the MCP session on the websocket. After it is cancelled, every browser connection is accepted and dropped immediately (`BrokenResourceError` in `_read_from_socket`).
- Fix, verified end to end with a client that allows 25s per call: `await_proxy_connection` is a polling loop that never cancels `_start_task`. `open_colab_browser_connection` waits only `COLAB_UI_WAIT=15s`. New tools `colab_status` (connected and port, no token) and `colab_wait_connected` (at most 25s). `colab_list_tools` and `colab_call` stay. The test was: `open` returned false because nobody had clicked, Connect was clicked after that, `colab_wait_connected` returned connected, and `colab_call get_cells` worked.
- Installed copy: `~/.local/share/colab-mcp/colab_mcp_visible.py`, launched by `uvx --from git+https://github.com/googlecolab/colab-mcp python <that file>` with `BROWSER="open -a Helium %s"`. The same source is committed as `scripts/colab_mcp_visible.py`.
- Procedure from here: one `open_colab_browser_connection`, read the port from `colab_status`, click Connect on the matching Helium tab, poll `colab_wait_connected`, then set the runtime to a T4 and run the Phase A smoke test. Do not call `open` again while waiting.
